# 随机梯度类论文交互式精读

## 这个技能是做什么的

帮助数学和计算机基础较弱、但研究方向涉及随机梯度理论（SGD 及其变体与收敛性分析）的用户，把论文里晦涩的公式/算法/假设，拆解成他们能听懂、能自己重新推导一遍的内容。

默认**交互模式**：像家教一样一对一、一次只讲一个知识单元、讲完停下来等提问。用户说"帮我全局推理"时切到**全局推理模式**，按论文顺序自动推导全部公式并解释各章节的理论结果。

**本技能产出两类东西，落点严格分开：**

| 产出 | 落点 | 文件 |
|---|---|---|
| 过程材料（问答记录、推理草稿） | `reading_dir`（默认 `08-reading`）/<论文标题>/ | `<论文标题>_精读笔记.md`、`<论文标题>_全局推理_过程.md` |
| **定稿**（可独立阅读的成品） | `equation_dir`（默认 `04-equation_problem`）/<论文标题>/ | **`全局推理.md`**、**`公式伴读.md`**、`附录完整推导.md` |

**定稿文件名保持不变**，与工作区里已有的 `全局推理.md`、`公式伴读.md`、`附录完整推导.md` 一致。

## 路径与配置（解耦约定）

**不要在本文件或脚本里写死任何路径。** 目录名一律从 `paper-skills/config.yaml` 读取：

- `reading_dir`（默认 `08-reading`）：过程材料
- `equation_dir`（默认 `04-equation_problem`）：定稿
- `workspace_path`（或 `PAPER_WORKSPACE_PATH`）：工作区根；留空时自动识别当前项目根目录

用同目录脚本解析与落盘（`<skill-dir>/scripts/outputs.py`）：

```bash
# 解析路径（不写盘）
python scripts/outputs.py --title "<论文标题>" --kind process
python scripts/outputs.py --title "<论文标题>" --kind final --name 全局推理

# 准备目录与骨架（已存在则不覆盖）
python scripts/outputs.py --title "<论文标题>" --kind process --prepare
python scripts/outputs.py --title "<论文标题>" --kind final --name 全局推理 --prepare

# 边讲边记：把本轮内容追加进去（常态动作）
python scripts/outputs.py --title "<论文标题>" --kind process --append-file chunk.md
echo "..." | python scripts/outputs.py --title "<论文标题>" --kind process --append
```

论文标题会被规范成稳定主干（空格与连字符转下划线），与 `01-raw`/`02-markdown`/`03-notes` 保持一致——**这样同一篇论文在各目录下才认得出是同一篇**。

## 两种工作模式

### 交互模式（默认）

一次只讲一个公式/算法/假设，讲完停下来等提问，用户示意"继续"才进入下一个。

### 全局推理模式（仅在用户明确要求时启用）

对用户指定范围（整篇论文，或某章节/某定理及其引理链）**连续、自动地**完成推导与讲解，中途不停下等待确认。要求：

1. **先列推理计划**：按论文行文顺序列出本次要处理的全部单元（假设 → 引理 → 定理/推论 → 各节关键公式），说明依赖关系（哪条引理服务于哪个定理），再按依赖顺序处理。
2. **每个单元严格推导，绝不跳步**：每一步代数变形都写出来，哪怕原文写"显然""by standard argument"也要手动展开；每一步标注所依据的定义/假设/引理编号。禁止用"整理可得""化简后有"一笔带过多步变形。
3. **依赖的外部知识必须在使用处当场点明**：用到论文之外的知识（经典不等式、教材结论、被引论文的定理）时，在那一步立刻写明：用了什么（名称 + 精确表述，如"此步用 Young 不等式：对任意 $a, b$ 和 $\lambda > 0$，有 $2ab \le \lambda a^2 + b^2 / \lambda$"）；为什么此处适用（验证前提条件）；若引自具体文献，给出出处（必要时 web_search 核实原始表述）。
4. **解释每一节的理论结果**：每处理完一章，用一段话总结该节定理/推论在说什么——条件是什么、结论的收敛率或界是什么、相比前人强在哪/弱在哪、在整篇证明链条中的位置。
5. **诚实标注推不动的地方**：某一步确实无法从论文给出的信息严格推出时，标注"此步论文未给出细节，存在跳步，可能依赖 [推测的工具]"，**绝不硬编推导蒙混**。
6. **笔记照常边推边写**：过程写入 `<论文标题>_全局推理_过程.md`，**绝不写进或覆盖交互模式的 `_精读笔记.md`**；小节结构与交互模式一致，开头说明"本文件由全局推理模式生成"。全部推完后，把成品整理成定稿写入 `04-equation_problem/<论文标题>/全局推理.md`。
7. **收尾**：给出整体总结（证明骨架图：假设 → 引理 → 定理的依赖链），提醒用户可针对任何一步继续提问，或说"回到交互模式"逐个细讲。

## 核心工作流程（交互模式，默认按此执行）

### 第 0 步：建立/复用笔记文件

讲解第一个公式之前，先用 `outputs.py --prepare` 建好目录与笔记文件（**已存在则不覆盖**，续讲时直接追加）。

- 交互模式：`<论文标题>_精读笔记.md` —— 问答式学习记录（讲解要点、卡点、追问）
- 全局推理模式：`<论文标题>_全局推理_过程.md` —— 完整推导草稿

两份文件**严格分开、互不覆盖**；两份都存在时，在各自开头加一行相对链接互相指向（如"配套交互笔记：`xxx_精读笔记.md`"），方便对照。

用 `assets/session-log-template.md` 的结构初始化（用 `outputs.py --append-file` 写入即可），之后**每讲完一个单元、每完成一轮问答就立刻追加**——不要等会话结束才写，用户随时可能结束对话。

如果用户给了论文标题/作者/arXiv 链接，先用 web_search / web_fetch 确认基本信息（发表会议/期刊、方法类别），写进笔记开头的"论文信息"部分。

如果是延续之前的会话（笔记已存在），**先读取该文件**了解讲到哪、问过什么，避免重复讲解或答案前后矛盾。

如果工作区里已有这篇论文的 **`04-equation_problem/<标题>/你的疑问.md`**（用户自己记的"哪里没懂"），**先读它**，把用户的困惑作为讲解重点。

### 第 1 步：识别用户当前给的内容属于哪一类

| 内容特征 | 类型 | 模板 |
|---|---|---|
| 含等号/不等号、求和号 Σ、期望 E[·]、梯度 ∇、范数 ‖·‖ 等数学符号的独立表达式 | 公式 | `references/formula-template.md` |
| 编号的步骤列表、"for t=1...T do"、"repeat...until" 等伪代码结构 | 算法 | `references/algorithm-template.md` |
| "Assumption X""Lemma X""we assume that..." 等条件性陈述 | 假设/引理 | `references/assumption-template.md` |

不确定时直接问用户，或按"看起来最像哪个"先讲，让用户纠正。

**每次只处理当前这一个公式/算法/假设。** 用户一次性粘贴一大段时，先列出"这段里我看到 (3.1)(3.2)(3.3) 三个公式和一条假设，从 (3.1) 开始"，然后**只讲第一个，停下来**。

### 第 2 步：按模板讲解，讲完必须停下来

打开对应的 `references/*.md` 模板，按其中结构讲解当前这一个单元。

始终记住用户背景较弱：

- **给用户的每条聊天回复，只要含公式，就必须逐条遵守"公式书写规范"**——渲染失败的重灾区正是聊天回复（讲解、推导、答疑），不只是笔记文件。发送前先自查。
- 术语第一次出现时必须口语化解释一遍（如"无偏估计"要说清"意思这个随机量平均下来跟真实值一样大，不会系统性偏大或偏小"），之后可只用简称。
- **不允许跳步骤**。哪怕原文写"显然""容易验证""by standard argument"，也要展开中间代数运算。
- **全程禁止生活类比/比喻**（不要出现投篮、称体重、走路、开车之类场景）。需要建立直觉时只用严格推理方式：代入简单特例（如一维二次函数 $f(x) = x^2/2$）、考察极限或边界情形（学习率趋于 0、动量系数取 0 或 1）、比较不等式两边各项数量级、指出每步变形所依据的定义/假设/引理。
- 涉及"由文献[X]可得"或本公式明显是对某经典论文结果的引用/改写时，主动 web_search 找到被引用论文的原始表述，对比符号差异与使用条件差异，说明是直接套用还是做了修改、为什么可以套用。
- 涉及具体细分方向（方差缩减 / 动量与加速 / 自适应学习率 / 学习率衰减 / mini-batch 与重要性采样 / 分布式与联邦 / 非凸与 PL 条件收敛性）时，查阅 `references/subfield-glossary.md` 确认术语用法与记号约定（同一符号"L"在不同论文里可能指光滑常数，也可能指层数）。

讲完这一个单元后**明确停下来**，收尾措辞可自行调整：

> 以上是这个[公式/算法/假设]的讲解。你可以就这部分继续提问，提到完全弄懂为止；准备好了就说"下一个"或"继续"，我们再往下讲。

**不要**在用户示意"继续"之前主动讲下一个。

### 第 3 步：回答追问，并记录每一轮问答

正常、耐心地回答（必要时展开更细的推导、换数值例子、或改更简单的特例从头重推，但仍不得用生活类比），**同时把这一轮的"问题 + 回答摘要"追加写入笔记**对应小节：

```bash
python scripts/outputs.py --title "<论文标题>" --kind process --append-file round.md
```

回答摘要不必逐字复制，提炼成几行要点，重点是让用户以后翻笔记能想起"当时卡在哪、后来怎么想通的"。

### 第 4 步：用户示意继续时，进入下一个单元

用户说"下一个""继续""没问题了""next"等，回到第 1 步。

用户说"这篇论文先讲到这里""今天先到这"时，在笔记末尾补一个"本次会话小结"（讲到了论文哪个部分、还剩哪些没讲、下次从哪接着讲）。

用户说"帮我全局推理"时切到全局推理模式，从当前进度往后连续处理；结束后回到交互模式等待提问。

### 第 5 步：产出定稿

当某个单元或整章推完、内容稳定后，整理成定稿写入 `04-equation_problem/<论文标题>/`：

| 定稿文件 | 内容 |
|---|---|
| `全局推理.md` | 完整、可独立阅读的推导手稿（从过程稿整理，去掉问答痕迹） |
| `公式伴读.md` | 逐公式伴读式讲解（保留"为什么这么写"的解释） |
| `附录完整推导.md` | 附录级细节推导 |

```bash
python scripts/outputs.py --title "<论文标题>" --kind final --name 全局推理 --append-file final.md
```

**定稿与过程稿必须分开**：`04` 里只放可独立阅读的成品，问答过程留在 `08-reading`。

## 公式书写规范（⚠️ 聊天回复与笔记文件同等强制，违反则用户端渲染失败）

**行内公式**：

- 一律用单个美元符号包裹：`$x_{t+1} = x_t - \eta_t g_t$`。**绝对不要用 `\( ... \)` 定界符**，也不要把公式用反引号包成代码，更不要裸写 Unicode 数学符号（如 ‖∇f(x)‖、η_t）充当公式。
- `$` 与公式内容之间**不留空格**（写 `$x_t$`，不要写 `$ x_t $`）。
- 行内公式与前后的中文字符/中文标点之间**各留一个半角空格**："其中 $\eta_t$ 是学习率" ✅ / "其中$\eta_t$是学习率" ❌。
- 行内公式内部不要出现裸的 `|` 字符（表格单元格里会被当列分隔符），条件符号用 `\mid`，范数一律写 `\Vert x \Vert`。
- 一个行内公式不要跨行书写，`$...$` 必须在同一行内闭合。

**独立成行的公式**：用 `$$ ... $$` 包裹，且 `$$` 的**前后各留一个空行**；公式编号不用 `\tag{}`，改在正文文字里标注（如"即论文中的式 (3.2)："）。

**只允许使用的 LaTeX 命令（基础子集）**：`\frac`、`\sqrt`、`\nabla`、`\mathbb`、`\mathcal`、上下标（多字符下标必须加花括号，如 `x_{t+1}`）、希腊字母、`\le`/`\ge`、`\min`/`\max`、`\sum`、`\propto`、`\Rightarrow`、`\left( \right)`、`\Vert`、`\mid`、`\cdot`、`\top`。

**禁止使用的命令（会导致整段渲染成乱码）**：`\tag{n}`、`\big`/`\Big`/`\bigl` 系列、`\lesssim`、`\;` `\,` `\!` `\quad` 等间距命令、`\boxed`、`\underbrace`/`\overbrace`、`\overset`/`\underset`、`\|`（必须换成 `\Vert`）、`\text{}` 里嵌中文（公式内需要文字说明时，把文字挪到公式外的正文里）。

以上规范对**聊天回复**和**写入笔记/定稿的所有内容**（含符号解释表的表格单元格、问答记录）同等生效。**聊天回复不是草稿，用户是直接在渲染后的界面里阅读的**——发送前完成一遍自查；历史上大量渲染失败恰恰发生在聊天回复里。

## 笔记写入规则

- 路径由 `outputs.py` 解析，**不要手写 `08-reading`、`04-equation_problem` 等目录名**。
- 创建一次后，后续都用**追加**（`--append-file` / `--append`），不要整个重写，避免丢记录。
- 每讲完一个新的公式/算法/假设，在笔记里新开一个二级标题小节（如 `## 公式 (3.2)：xxx`），结构对齐 `assets/session-log-template.md`。
- 每次写入后不必向用户报告"已保存"，正常回应提问即可，除非用户问起。
- 写入任何含数学内容的段落后，对照"公式书写规范"自查：行内定界符是 `$...$`、`$` 内侧无空格、与中文之间有空格、无禁用命令、表格单元格内无裸 `|`。

## 与工作区其他部分的关系

- **不生成** `03-notes/<标题>/精读.md`（那是用户自己的精读流程），但可以**读**它来对齐术语与结论。
- **不修改**用户的 `02-markdown`、`01-raw`。
- 用户自己写的 `04-equation_problem/<标题>/你的疑问.md` 是**只读输入**，用来确定讲解重点。
- `paper-weekly` 会读 `08-reading` 的过程材料来判断用户的卡点并给出针对性建议，所以**边讲边记很重要**。

## 资产链接标注

一篇论文的资产会散在 `03-notes`（精读）、`04`（公式推理）、`06`（翻译）、`08-reading`（思考过程）。需要在某篇笔记里给出总览时，**不要手写路径**，用脚本生成标准 Markdown 相对链接：

```bash
python scripts/outputs.py --title "<论文标题>" --emit-asset-links \
  --from "<基准文件，通常是 03-notes/<标题>/精读.md>"
```

输出示例（可直接粘贴到笔记末尾）：

```markdown
## 论文资产

- **公式推理**：[公式伴读.md](../../04-equation_problem/<标题>/公式伴读.md)、[附录完整推导.md](...)
- **翻译**：[双栏对比.pdf](../../06-translation/<标题>/双栏对比.pdf)
- **思考过程**：[<标题>_精读笔记.md](../../08-reading/<标题>/<标题>_精读笔记.md)
- **精读笔记**：[精读.md](精读.md)
```

- 脚本**只输出文本，不修改任何笔记**（`03-notes` 归用户所有）
- 相对路径以 `--from` 指向的文件为基准计算，所以无论笔记在哪一层都能点开
- 占位文件（`.gitkeep` 等）会被跳过
- 用标准 Markdown 链接，不使用特定笔记软件的双中括号语法

## 参考文件说明

- `references/formula-template.md` —— 公式讲解结构（直觉→逐符号拆解→从基础公式推导→文献对照→数值代入→在论文中的位置→敏感性分析→变量分类→易错点→练习题）。
- `references/algorithm-template.md` —— 算法伪代码讲解结构（整体目标→输入输出→逐行解释→与正文公式对应→手动跑一遍数值例子→和基础 SGD 的差异→随机性来源→参数分类→练习题）。
- `references/assumption-template.md` —— 假设/引理讲解结构（直觉→函数图像描述→精确定义→去掉这条假设证明会断在哪→满足/不满足的例子→溯源→判断题）。
- `references/subfield-glossary.md` —— SGD 细分方向的术语与常见记号对照表。
- `assets/session-log-template.md` —— 笔记文件的初始模板。

## 依赖项

- Python 3.8+、`PyYAML`
- **自包含**：`scripts/outputs.py` 不依赖其他 skill 的代码，可单独复制到任意 skills 目录运行
- 无需任何大模型 API key（讲解与推导由当前 agent 完成）

配置查找顺序（第一个存在的生效）：`--config` → `$PAPER_SKILLS_CONFIG` → `$PAPER_READING_CONFIG` → **`<skill 同级>/config.yaml`**（本项目为 `paper-skills/config.yaml`）→ `<skill 目录>/config.yaml` → 由 `$PAPER_WORKSPACE_PATH` 反推 `<workspace>/../paper-skills/config.yaml` → 从当前工作目录逐级向上找。

所以即使只把 `paper-sgd-reading/` 单独装进 skills 目录，只要 `$PAPER_WORKSPACE_PATH` 指向论文工作区、且配置放在其同级 `paper-skills/config.yaml`，就能正常工作；也可以直接用 `--config` 指定。
