\section{Scope and Problem}
\label{sec:scope}
A classifier prediction may be passed through an acceptance rule that determines
whether the prediction is retained or rejected. Confidence Gate uses only the
largest class probability reported for that prediction. The supplied proposal
sets the threshold to $0.8$ and keeps the classifier fixed. This manuscript
specifies that behavior; it does not establish whether the rule is useful on any
particular task.

\section{Decision Rule}
\label{sec:method}
Let $x$ denote an input. Write $p_k(x)$ for the class probability reported by the
fixed classifier for class $k\in\{1,\ldots,K\}$, and let $\widehat y(x)$ denote
its original predicted label. This notation represents the supplied description
of class probabilities; it does not specify a model architecture or a training
procedure. Define the score and acceptance indicator as
\begin{equation}
\label{eq:gate}
 s(x)=\max_{1\leq k\leq K} p_k(x),
 \qquad a(x)=\mathbf{1}\{s(x)\geq 0.8\}.
\end{equation}
Confidence Gate returns the original prediction when $a(x)=1$ and a rejection
symbol $\bot$ when $a(x)=0$:
\begin{equation}
\label{eq:output}
 g(x)=\begin{cases}
 \widehat y(x), & s(x)\geq 0.8,\\
 \bot, & s(x)<0.8.
 \end{cases}
\end{equation}
In particular, a score exactly equal to $0.8$ is accepted. Rejection provides no
alternative label in the supplied rule. The classifier's original prediction
is retained, so the gate does not introduce a separate label-selection or tie-breaking
procedure. How the classifier produces its probabilities and predicted labels
is not specified.

Operationally, the rule takes the fixed classifier's reported probabilities and
prediction, computes the maximum probability, compares it with $0.8$, and either
passes through the prediction or returns $\bot$. The material supplies no
rationale for selecting $0.8$ and no threshold-selection experiment. The value
is therefore a fixed specification, not an empirically optimized parameter.

An author-designed evaluation could examine how frequently the rule accepts
predictions and how often those accepted predictions are wrong. For clarity,
if labeled evaluation examples $(x_i,y_i)_{i=1}^n$ become available, one possible
reporting convention is empirical acceptance frequency
\begin{equation}
 \widehat C=\frac{1}{n}\sum_{i=1}^n a(x_i),
\end{equation}
and accepted-prediction error
\begin{equation}
 \widehat R=\frac{\sum_{i=1}^n a(x_i)\mathbf{1}\{\widehat y(x_i)\neq y_i\}}
 {\sum_{i=1}^n a(x_i)},
 \quad\text{when }\sum_{i=1}^n a(x_i)>0.
\end{equation}
If no prediction is accepted, the latter quantity is undefined and should be
reported as such. These are proposed descriptive reporting definitions, not
measurements, author-approved study choices, or a theoretical guarantee.
Any comparison must also report acceptance frequency so that error figures can
be interpreted with their retained sample size. The authors must decide the
protocol and appropriate comparisons for the actual task.

\section{Related Work, Limitations, and Conclusion}
\label{sec:limitations}

The current material supports the definition of Confidence Gate and its
inclusive threshold boundary. It does not support a claim about robustness,
calibration, fairness, computational savings, or deployment suitability.
The consequences of rejecting an input depend on an unspecified downstream
procedure. There is also no empirical basis for recommending $0.8$ across
classifiers, datasets, or applications.

Confidence Gate accepts a fixed classifier's prediction precisely when its
maximum reported class probability is at least $0.8$. This draft makes that
rule explicit and exposes the missing evidence. Assessing its value requires
author-reviewed research materials; the draft is not ready for submission.
