# 算法讲解模板

用于讲解一段算法伪代码或算法流程图(比如论文里的 "Algorithm 1")。

## 1. 一句话总览

不涉及任何符号,说明这个算法整体在做什么事情、解决基础 SGD 的什么问题
(比如"每一步不算全部数据的梯度,只随机抽一小部分来估计,省时间但引入噪声"这类)。

## 2. 输入输出

列出算法的输入,并分类:
- 哪些是数据(训练样本、数据分布)
- 哪些是超参数(学习率、批大小、迭代总数T、动量系数等,人工设定不会被算法本身更新)
- 哪些是初始值(初始点 x_0、初始动量 m_0 等)

再列出算法的输出(通常是最终迭代点、或者迭代过程中的某个平均点)。

## 3. 逐行解释

伪代码每一行单独过一遍:
- 这一行在做什么运算
- **这一行里出现的每一个符号,都在读到这一行时立刻解释**(见公式模板第 3 节的"逐个就地解释"规则):
  循环下标与它的取值范围、赋值号左边的量是谁算出来的、条件判断里比较的是哪两个量、
  裁剪/取范数用的是哪一种范数、论文自定义的缩写和常数分别指什么。
  解释完这一行才继续下一行。**不要**在算法开头先甩一张覆盖全篇的符号总表,
  也**不要**把整段伪代码讲完之后再统一回顾符号——那样等于没解释。
  同一符号在后面的行里再次出现时,一句"这里的 $\eta_t$ 仍是第 3 行算出来的那个步长"回指即可。
- 为什么需要这一行(删掉会发生什么、这一行解决了什么问题)
- 这一行对应正文里的哪个公式编号(把伪代码和论文正文的公式一一对应起来,
  比如"第4行就是正文里的公式(3.2)")

## 4. 手动跑一遍数值例子

设一个非常小的例子(比如2维参数、3-4个训练样本、跑2-3轮迭代),把每一行代入具体数字,
完整跑一遍算法,每一步列出中间结果。让用户能对照着自己动手算一遍。

## 5. 和基础版本的对比

这个算法相比最基础的 SGD(x_{t+1} = x_t - η∇f(x_t; ξ_t))多了/改了哪一步?
这一步是为了解决基础 SGD 的什么缺陷(方差大、收敛慢、需要精细调学习率、
容易陷入鞍点、对不同参数的更新步长没有区分等)?

## 6. 随机性来源

如果算法里有随机采样步骤(随机选一个样本 / 一个 mini-batch / 随机坐标等),
明确指出这个"随机性"具体体现在伪代码的哪一行,并说明:后续论文里对这个算法的
期望/方差分析,分析的正是这一行引入的随机性。

## 7. 参数分类

列出算法涉及的量分别是:
- 模型参数(会被这个算法在迭代过程中更新的,比如 x_t 本身、动量 m_t)
- 超参数(需要在跑算法之前人工设定、跑的过程中不会被更新的,比如学习率、批大小)

## 8. 复杂度/开销提示(如果论文提到)

如果论文比较了这个算法和其他算法每一步的计算/存储开销(比如是否需要存储所有样本的梯度、
是否需要额外的内存),简要说明一下,帮助理解"这个算法为什么值得用"。

## 9. 练习题

给一道简单的练习题,让用户手动模拟算法跑一步(给定具体的初始值和一个采样结果),
并给出答案。

## 10. 研究审计

- **净增量**：相对基础 SGD 和最接近算法，真正不可约的新步骤是什么？只是重参数化或已知模块组合时要直说。
- **理论-实现一致性**：伪代码是否需要理论里未计入的 oracle、全梯度、额外状态、同步或未知常数？
- **公平成本**：单步复杂度、总 oracle 次数、内存、通信和调参成本如何；收敛优势是否被额外成本抵消？
- **失效区域**：在哪些噪声、曲率、批量或规模条件下预计退化？
- **最小判别实验**：设计一个能区分作者机制解释与更简单替代解释的对照或消融。
